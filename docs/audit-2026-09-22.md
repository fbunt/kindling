# Kindling audit — 2026-09-22

**Method.** Eight independent review lenses (web security, sandbox/deploy security, architecture,
code quality, UX, UI, LLM design, tests & ops) each read their full scope; every medium-or-higher
finding was then handed to a separate skeptic instructed to refute it; a completeness critic looked
for what all eight missed; a final agent synthesized. 73 agents, ~3.8M tokens, analysis-only.
99 findings survived: 5 high, 27 medium, 53 low, plus 14 whose severity the skeptics revised
(mostly downward). **No finding was refuted outright** — the skeptics adjusted severities instead,
so treat "low" items as plausible-but-unverified and the high/medium items as independently
confirmed. One skeptic died on a schema error while confirming the "no CSP / security headers,
unpinned CDN scripts" finding; it is reinstated below by hand. The `--userns=keep-id`, 1 MB form
cap, env-key auto-login, and worker fd-1 findings were additionally spot-checked by the
orchestrator against the source and Starlette 1.2.1.

Spot-check caveat on Fix-first 1: the dataset is a directory of world-readable parquet parts,
so dropping `keep-id` should not break the read-only mount, but verify with one query after the
change.

**Status.** Items are struck through and marked DONE as fixes land; the file is deleted once all are.

## Overall assessment

The project is in good shape where it decided to be careful. The runtime split (schema-only `query_engine`, provider-agnostic `chat_loop`, the pool/worker execution boundary) is clean and the three decision records are honoured by the code. The worker argv is a solid baseline (`--network none`, `--read-only`, `--cap-drop ALL`, no-new-privileges, memory/pids caps, `:ro` parquet), the JSONL protocol bounds frames on both sides, the plots route allowlists names, markdown goes through DOMPurify, and the pool/argv tests that exist are deterministic and well-built. The biggest strength is that the security boundary the docs promise (decision 0002) really is the container, with one exception noted below.

The biggest liability is that the app's operational envelope is wider than the code enforces. Two things stand out. First, `--userns=keep-id` (`app/sandbox/pool.py:116-117`) maps the worker to the real host uid, so the "non-root second line" is currently false on podman and a runtime escape lands as the user who owns the podman socket and `~/.ssh`. Second, the access story: every launch path publishes cleartext HTTP on `0.0.0.0:8000`, `GET /api/auth/status` mints a session on the operator's key for any cookieless request, and the client picks the model, so if the port is reachable the paid endpoint is anonymous. Behind those, the most user-visible defect is that history round-trips every plot and upload as base64 and hits Starlette's 1 MB form-part cap after a few plots, at which point the UI hangs on "Thinking..." forever. The test suite and bench are careful where they exist but CI never touches the container, the worker protocol, or `chat_loop.py`, and the bench cannot yet measure the cost half of the Flash-vs-Pro comparison it is meant to settle.

## Findings by area

### Security (web)

- **Env-key auto-login makes the endpoint anonymous; no rate limit; client picks the model** [high, M] — `app/routes/auth.py:55-58`, `app/routes/chat.py:39`, deploy files — Any cookieless request gets a session on `GEMINI_API_KEY`, then up to 20 model calls per turn on any model string it names. Fix: read-only status endpoint plus explicit opt-in, loopback bind or shared secret, server-side model allowlist, a small per-session turn limiter.
- **No TLS anywhere; key POSTed in cleartext; cookie not `Secure`, 14-day `max_age`** [high, M] — `app/main.py:103-106`, `app/static/app.js:279-282`, `deploy/kindling.container:19`, `scripts/run.sh:91`, `compose.yaml:17`, `Makefile:21` — The stated prod target is a GCP VM; nothing in deploy/ terminates TLS. Exploitation needs a public firewall rule, so this is a missing hardening step rather than an out-of-the-box exposure. Fix: Caddy sidecar (or IAP/SSH tunnel enforced by firewall), `https_only` gated by env, shorter `max_age`; add the heartbeat first.
- ~~**History form field hits the 1 MB part cap; UI hangs**~~ **DONE 2026-09-23** [high, M] — `app/routes/chat.py:39-41, 171-186`, `app/static/app.js:336, 349-367, 428-431` — Real plots are 124–228 KB, so 3–4 plots or one photo breaks every later turn with a spinner and no error. Fix: client non-2xx handling now; server-side plot cache keyed by name later.
- ~~**Client image/history unbounded and unvalidated; malformed input 500s**~~ **DONE 2026-09-23** [medium, S] — `app/routes/chat.py:47-98` — `msg["image"]["mime"]`/`b64decode` run before the stream starts and outside any handler; uploads have no size or MIME cap and `filename` goes into the prompt. Fix: pydantic `TypeAdapter(list[HistoryMsg])` → 422, reject >10 MB, allowlist png/jpeg and sniff magic, cap history.
- **External `<img>`/`<a>` in rendered markdown enables exfiltration via web_search injection** [medium, S] — `app/static/app.js:89-92`, `app/tools.py:142-151` — Default DOMPurify keeps remote image sources; a grounded page can make the model emit a beacon URL. Fix: `uponSanitizeAttribute` hook restricting `src`, plus a CSP `img-src 'self' data: blob:`.
- **No CSP or other security headers; CDN scripts unpinned and without SRI, including DOMPurify itself** [medium, S] — `app/static/index.html:8-9, 90-94`, `app/main.py:97-113` — marked has no version at all, dompurify floats on `@3`, highlight.js on `@11`, none carry `integrity=`; the app sets no `Content-Security-Policy`, `X-Content-Type-Options`, `Referrer-Policy` or `X-Frame-Options`. The sanitizer that stands between model/web output and the DOM is itself an unpinned dependency. Fix: pin exact versions with SRI (or vendor the five files) and add a header middleware with a CSP of `default-src 'self'; img-src 'self' data: blob:; script-src 'self' https://cdn.jsdelivr.net`. (Skeptic confirmed; overlaps the UI-lens SRI item below.)
- **Raw exception text reaches the browser (chat error, login error)** [low, S] — `app/routes/chat.py:159-161`, `app/routes/auth.py:39-40`, `app/static/app.js:288` — Inconsistent with the canned SandboxBusy/WorkerDead messages; also ugly UX for a mistyped key vs a network blip. Fix: map exception classes to short strings, keep detail in `logger.exception`.
- **Keystore has no TTL; status GET mutates state and makes logout a no-op in env-key mode** [low, S] — `app/keystore.py:12-27`, `app/routes/auth.py:42-66` — Fix: single sentinel token for the env key, `(key, created_at)` with eviction at `max_age`.
- **`/api/chat` is CSRF-able from other localhost ports** [low, S] — `app/routes/chat.py:35-45` — Fix: reject mismatched `Origin`, or require a custom header app.js sets.
- **API key left in the password field after login/logout; no `autocomplete=off`** [low, S] — `app/static/app.js:279-286, 478-483`, `index.html:19`.
- **`.env` is 0644** [low, S] — `chmod 600`; add a startup warning.

### Security (sandbox/deploy)

- ~~**`--userns=keep-id` runs the worker as the host user**~~ **DONE 2026-09-23** [high, S] — `app/sandbox/pool.py:116-117`, `Containerfile:37-39` — Verified on this host: without keep-id uid 1000 maps to ~525287 which owns nothing; with it, `~/.ssh` (0700) and the podman socket (0660) are reachable after an escape. Fix: drop it (or `--userns=auto`); gate behind an env var only if a non-world-readable dataset ever needs it.
- **Host timeout leaves a live worker with a desynced pipe; fd 1 is forgeable** [medium, S] — `app/sandbox/pool.py:211-226, 267-281`, `app/sandbox/worker.py:155-162, 200-201` — The 510 s host timeout fires exactly when the worker's 480 s soft timeout could not (GIL held in C), and the late frame answers the next `run_query` in the same turn; `os.write(1, …)` from query code does the same. Fix: kill on `WorkerDead`, per-request ids, `dup2(2, 1)`, plus a container test.
- **Pool degrades silently to zero workers; failed refills never retry** [medium, S] — `app/sandbox/pool.py:338-345, 455-473, 403-407` — A wrong `KINDLING_WORKER_PARQUET_PATH` yields a "healthy" app where every turn blocks 120 s then says "sandbox is busy". Fix: raise in `start()` on empty pool, spawn on demand or bounded retry in refill, log podman stderr.
- **Quadlet lacks `Requires=podman.socket`; enable-linger undocumented** [medium, S] — `deploy/kindling.container:13-15, 36-40` — Boot-order race produces the empty-pool state above and `Restart=always` never fires. Fix as in Fix-first 6.
- **Cleartext HTTP on all interfaces in every launch path** [medium, M] — merged with the TLS finding above; publish on `127.0.0.1` in all four files now.
- **`fedora:41` base is EOL; no digest pinning of bases or actions** [medium, S] — `Containerfile.app:11`, `Containerfile:8`, `.github/workflows/ci.yml:22-68` — The image holding the host socket receives no OS updates. Fix: bump base (or `python:3.12-slim` + `podman-remote`), digest-pin `FROM`, SHA-pin actions, Dependabot for both ecosystems.
- **Worker/app pins have drifted from uv.lock despite the Containerfile claiming otherwise** [low, M] — `Containerfile:4-20` (polars 1.38.1 vs lock 1.41.2, numpy/matplotlib/pyarrow/tabulate likewise), `Containerfile.app:30-32` installs the rest unpinned. Fix: `uv export --locked` into requirements files consumed by both images; CI check that `==` pins match the lock.
- **Worker replies not shape-validated; non-PNG plot bytes reach `plots/`** [low, S] — `app/sandbox/pool.py:175-209` — Fix: reject non-dict frames, check PNG magic and cap decoded size.
- **In-flight worker leaks at shutdown; orphaned workers never self-terminate** [low, S] — `app/sandbox/pool.py:380-399`, `app/sandbox/worker.py:216-231` — Fix: track a `_leased` set killed in `drain()`; idle-exit in the worker.
- **App container is root-in-container with no cap-drop/read-only** [low, M] — `Containerfile.app` — Defence in depth only; does not close the socket path decision 0003 already accepts.
- **No `--cpu-shares`/`--oom-score-adj` on workers** [low, S] — `app/sandbox/pool.py:91-128` — Self-DoS only under one-VM-per-user; add both flags, warn if cap exceeds MemTotal.
- **`GEMINI_API_KEY` on the podman command line in run.sh/Makefile; `.env` not in `.containerignore`** [low, S] — `scripts/run.sh:87`, `Makefile:28-29` — Dev-only paths; Quadlet already uses `Secret=`. Fix: `--env-file`, guard the Makefile `-e`, ignore `.env*`.
- **`/tmp` tmpfs is 512 MB while `POLARS_TEMP_DIR=/tmp` under a 110 GB cap; `--http-proxy` default on; no `--pull=never`** [low, S] — `app/sandbox/pool.py:101-102`.

## Larger investments

1. **Server-side session state (transcript + plot bytes).** _Partially addressed 2026-09-23: plots and uploads travel by reference with a 2-turn image window; the transcript itself is still client-side._ Store history and plot/upload bytes per session token on the server and send only references from the client. One change retires the 1 MB cap, the unbounded per-turn payload, the transcript/history divergence, the reload-loses-everything problem, and gives a natural place to cap re-embedded images and carry executed code forward. Depends on deciding whether transcripts persist across process restart (the plots dir is currently wiped on startup) and on the pydantic history schema.
2. **A deployment story with TLS and access control.** Loopback bind, Caddy sidecar (or IAP + firewall) as a second Quadlet unit, `https_only` cookie, `Requires=podman.socket`, enable-linger, `/healthz` + `HealthCmd`, the SSE heartbeat, and GHCR images actually consumed by the Quadlet. Depends on doing the heartbeat first (or every long query dies behind the proxy) and on choosing between "reachable with a secret" and "tunnel only".
3. **CI that exercises the boundary.** Build the worker image in the test job, run the container tests, ping the built image before push, add `tests/test_chat_loop.py`, derive both images' pins from `uv.lock` with a drift check, digest-pin bases. Depends on `ubuntu-latest` docker/podman being acceptable as the CI runtime.
4. **Make the bench able to answer the Flash-vs-Pro question.** Prompt fixes (streaming, row cap, eco2/3) land first, then a shared `build_turn_config`, token/thinking accounting, a run fingerprint, schema-based scalar extraction, and ~8 questions covering plots/labels/multi-turn/abstention/disclosure. Without the fingerprint and token columns, comparing runs made before and after the prompt fixes confounds model with prompt. Depends on recomputing ground truth on the moved parquet.
5. **UI pass for first-time and mobile users.** Empty-state onboarding card fed by a `GET /api/dataset`, plots inlined from `data.plots` with a mobile drawer, CSV/PNG export, ARIA live region and labels, focus-visible controls, table scroll wrapper, `/api/config` for the model badge and the planned two-option selector. Depends on nothing else; can be done incrementally.

## Not worth doing

- Treating "plots inaccessible on mobile" as high: plots do render inline when the model follows the prompt; keep it medium and fix by always inlining from `data.plots`.
- Deriving the worker memory cap from `MemTotal`: 110g is a deliberate per-VM budget (decision 0001); add a startup warning when the cap exceeds physical RAM and stop there.
- Hardening the app container (non-root, cap-drop) as a security fix: it does not close the socket path decision 0003 already accepts; do it only as cheap hygiene.
- Treating the guard-verdict parsing bug as a security hole: guards are not the boundary (0002); fix it for logging fidelity, nothing more.
- A `DatasetConfig` registry or multi-dataset support: no roadmap item asks for it and the current triangulation misbehaves in no real launch path. Document "MTBS only", `strict=False`, and move on.
- A light theme: dark-only is a legitimate choice for a single-user tool; add `prefers-reduced-motion` and leave the palette unless you want it.
- Keystore TTL machinery beyond a single sentinel token for the env key: the growth is real but tiny at one VM per user.
- Regenerating the paper's 25 bench questions: keep them intact for reproducibility; add a new category instead.
